| D33 | 2026-11-12 | **Karachi data pipeline** lives in `data/karachi/pipeline/` (plain Node, no dependencies; `node data/karachi/pipeline/run.mjs`): parse → gazetteer → OSM suggestions. Places are merged **only** by a deterministic normalised key or by the human-curated `aliases.json`; fuzzy near-matches, generic names ("Petrol Pump") and roads are listed in `build/review.md` for a person. OSM supplies **suggested** coordinates and `name:ur`; a person confirms each one and the entry records `locationSource: "osm"`. Re-running never overwrites hand-entered fields. | A wrong merge invents transfers that don't exist, which is the worst kind of wrong data. | D34 | 2026-11-13 | **Auto-merge near-spelled places** in the gazetteer step (amends D33's "only by key or aliases.json"): pairs with similarity ≥ 0.8 and the same numbers (incl. roman numerals) merge, using **complete linkage** (every member of a cluster must be ≥ 0.75 similar to every other). Names that merely *contain* each other ("Defence" / "Defence Society", "Station" / "T.V Station") are **not** auto-merged. `aliases.json` `doNotMerge` vetoes a wrong merge. Route codes listed twice whose stops overlap ≥ 80% both ways merge into the longer listing (18-K, 16-F). | The owner reviewed the candidate list: the near-spellings are almost all real duplicates, and hand-merging 900 pairs isn't worth it. But merging the whole list transitively fused 162 names (Cantt Station + Golimar + Drigh Road + Korangi…) and "Tower + Keamari" into single places, which would invent transfers across the city; complete linkage and skipping "contains" pairs prevents that. | A wrong merge shows up in use: add it to `doNotMerge`. |
| D35 | 2026-11-13 | **The app runs on the pipeline's network** (`data/karachi/network.json`, copied to `app/src/services/api/mock/fixtures/network.json` by `pipeline/run.mjs`), built from **automatically chosen OSM locations** with no hand check (amends D33's "suggestions only" and fires D25's trigger). Guards: generic names get no location; roads only if OSM has a place/station of that name; ambiguous names take the candidate nearest their route neighbours, and none if all are > 4 km off; points > 8 km from their neighbouring stops and stops that make a route detour far off and back are dropped. Stops without a location are left out of routes; shapes are straight lines. Urdu names: hand-entered, else OSM `name:ur` (only when OSM's name is ours), else the **English name** (no machine translation). Every variant is `source: "text-2009+osm-unverified"`, and the About screen warns about it. The D25 sample network moves to `__tests__/fixtures/sample-network.json` for the unit tests that assert exact trips. | The owner chose to get the app running on real routes now rather than fill in ~1,300 locations by hand. A missing stop is safer than a wrong one, so every guard drops rather than guesses. First build: 326 of 342 routes, 306 stops; the planner finds a trip for ~96% of random stop pairs. | Hand-set `location`s in `gazetteer.json` always win, so coverage and accuracy improve with each re-run. Revisit before any public release: routes must be confirmed as still running (the text is from 2009) and the busiest stops checked on the map. |
